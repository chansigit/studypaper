## Recommended next steps

The following weaknesses should be addressed to improve reproducibility:

1. **Code availability (✗)**: Publish fine-tuning scripts, model checkpoint (RoBERTa-large-PM-M3-Voc), and RegulaTome split details on a public repository (GitHub or Zenodo). This is the single largest blocker for independent reproduction.

2. **Hyperparameters (✗)**: Release a supplementary table listing all hyperparameters: RoBERTa learning rate, batch size, epochs, warmup steps; FAVA latent dimension and encoder depth; Jaccard threshold; FDR alpha; confidence thresholds per relation type; orthology database and version (FedCoder).

3. **Random seeds (✗)**: Report confidence intervals (95% CI) from ≥3 independent fine-tuning runs with different random seeds. If computation is prohibitive, at least report bootstrap confidence intervals on the test set.

4. **Hardware (✗)**: Document GPU type (e.g., A100, H100), memory, cluster size, and wall-clock training/inference time. This is essential for computational reproducibility and resource planning.

5. **Evaluation scripts (partial)**: Publish per-relation-type F1, precision, recall (Table S1) and a precision-recall curve as a function of confidence score threshold. Release evaluation code or detailed pseudocode in supplementary materials. This allows users to assess reliability per regulatory type (critical for a multi-label task).

6. **Data availability (partial)**: Explicitly state RegulaTome train/validation/test split (PMID list or stratification strategy), PubMed/PMC corpus snapshot date, SIGNOR/KEGG/Reactome version/date, cellxgene and EBI Atlas version/date and filtering criteria. This anchors reproduction to fixed snapshots.
